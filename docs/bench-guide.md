# VPS 跑分与采购评估指南

> 面向场景：**黑五 / 周年庆挑 VPS 时，怎么用这个项目里的跑分功能做决策。**
>
> 读不懂某一段可以直接跳到 [「三档怎么选」](#三档怎么选)。

---

## 一、这个功能解决什么问题

买 VPS 时，商品页上的参数**几乎没有参考价值**：

| 商品页写的 | 实际可能是 |
|---|---|
| 2 核 / 4G / 50G SSD | 磁盘是超售的，写 500MB/s 实际只有 80MB/s |
| "10Gbps 端口" | 你所在的运营商到它这条线路很差，实际只有 2Mbps |
| "独享 CPU" | 宿主机超售 3 倍，你抢不到核心就变 0.5 核 |
| "不限流量" | 晚高峰 QoS 限速到 1/10 |

**同配置的两台机器，实际表现能差 10 倍。** 跑分功能的作用就是把「商品页参数」翻译成
「这台机器在我这儿到底能跑多快」。

它做两件事：

1. **服务器侧体检** —— 通过 SSH 直接在机器上跑基准测试，测出 CPU / 磁盘 / 网络 / 内存 / 稳定性的真实水平
2. **给出分数与评级** —— 把一堆原始数据（MB/s、ms、分数）换算成 0–100 的分和「优秀 / 良好 / 够用 / 偏低 / 很差」的评级，方便横向对比

## 二、快速上手（3 步）

### 第 1 步：先给新服务器接上 SSH 公钥

跑分完全靠 SSH 连过去执行命令。**新机器要先能免密登录。**

关键概念（很容易搞反）：

- **私钥** 永远留在**你自己的电脑上**（`~/.ssh/` 下面），**绝不上传到服务器**
- 上传到服务器的是**公钥**，放在服务器的 `~/.ssh/authorized_keys` 里

在这个项目里，本机有一把给服务器用的专用密钥，每台服务器在配置里各自指定用哪一把。
项目根目录有个 `deploy_key.ps1` 可以一键把公钥部署到所有服务器（需要你输一次密码）。

```powershell
# 只给名字匹配的那台部署（推荐，避免一台台来）
powershell -ExecutionPolicy Bypass -File .\deploy_key.ps1 -Name 新加坡
```

也可以用云厂商控制台的 VNC / Workbench 登录，手动把本机 `~/.ssh/<你的密钥名>.pub`
的内容追加到服务器的 `~/.ssh/authorized_keys`（权限 600）。

> **好消息：接好公钥后不需要在远端装任何东西。**
> 监控、跑分、项目同步、计划任务全部是直接跑 shell 命令，不需要 agent、不需要脚本。

### 第 2 步：跑一次「快速体检」

- 首页顶部点 **跑分** → 弹出批量跑分面板
- 点 **全部快速体检** → 串行跑完所有服务器（约 15 秒/台）

或者：侧边栏进 **服务器** → 目标服务器卡片 → **跑分** 按钮 → 选档位 → 开始。

### 第 3 步：看结果

- 弹窗里会出总分环形图 + 各维度分数 + 明细表
- 侧边栏 **跑分评估** 页可以横向对比所有机器（谁高谁低一目了然）

## 三、三档怎么选

| 档位 | 耗时 | 测什么 | 远端要什么 | 什么时候用 |
|---|---|---|---|---|
| **快速体检** | ~15 秒 | CPU 型号/主频/核心数、磁盘顺序读写、下载速度、延迟、内存、负载 | **什么都不用** | 快速横向对比、先筛掉明显差的 |
| **标准跑分** | ~10 分钟 | YABS 全套：fio 深度磁盘测试、sysbench CPU、iperf3 带宽、Geekbench 6 单核/多核 | 能访问 YABS 下载源 | 想认真评估 CPU 和磁盘 |
| **完整评估** | ~15 分钟 | 标准档全部 + 路由追踪、IP 质量、 流媒体解锁 | 能访问多个第三方站点 | **买之前必跑** |

### 「低优先级」模式

三个档都有这个开关，勾上之后：

- 远端命令用 `nice -n 19` + `ionice -c 3` 包裹 —— 这两个会被子进程继承，
  所以 fio / sysbench 全都自动降权，**几乎不影响线上业务**
- **自动跳过 iperf3**（带宽压测）—— 这个降权也压不住，会打满带宽
  改用快速档那种轻量限速下载来估带宽

> ⚠️ 你买的机器上如果已经跑着业务，**标准档和完整档务必勾上「低优先级」**。

## 四、分数怎么读

### 总分怎么来的

维度权重参考 VPSBenchmarks 官方指标权重表：

| 维度 | 权重 | 看什么 |
|---|---|---|
| CPU | 30% | Geekbench 6 单核分为主、sysbench 为辅 |
| 磁盘 | 25% | 顺序读写（fio 512MB / 1G） |
| 网络 | 20% | 下载速度、延迟（取国内组） |
| 内存 | 15% | 容量 + swap |
| 稳定性 | 10% | 负载、运行时间、失败项 |

> **注意分数波动**：同一台机器两次跑分可能差 5–10 分，主要来自网络维度（带宽测速每次不同）。
> **单次跑分只是一个数据点，别拿它当结论。**

### 评级对照

| 分 | 评级 | 含义 |
|---|---|---|
| 85+ | 优秀 | 超过绝大多数同配置机器 |
| 70–84 | 良好 | 正常水平，可以买 |
| 55–69 | 够用 | 能跑，但别指望性能 |
| 40–54 | 偏低 | 明显超售或配置缩水 |
| < 40 | 很差 | 谨慎，可能是被回收的超售机 |

### 「可信度」是什么

快速体检档能测的项有限，会显示**数据覆盖**百分比（比如 70%）。
它表示这次分数有多少比例的数据是真测出来的、其余是估算的。
**可信度低于 100% 时，说明有维度是按经验值补的**，这时分数只能当粗筛。

## 五、⚠️ 最重要的一件事：服务器侧延迟 ≠ 你访问它的延迟

**这一节决定了你会不会买错机器。**

跑分里那个「延迟」测的是：

> **这台机器 → 各公共服务** 的延迟（反映的是它的**出口网络**质量）

而你真正在意的是：

> **你（家里/公司）→ 这台机器** 的延迟（这才是你的使用体验）

**这两件事不一样。** 举个例子：一台在首尔的机器，到它隔壁的 Cloudflare 节点只要 4ms
（看着特别漂亮），但你从国内访问它要 40ms+ —— 那个 4ms 对你毫无意义。

### 所以采购决策要看「本地侧」延迟

项目里带了 `tools/local_speedtest.py`，**在你自己电脑上跑**：

```bash
python tools/local_speedtest.py <候选机器IP> [更多IP...]
```

它会测 TCP 握手 RTT、ICMP、HTTP 首字节（可选测下载带宽），并给出 **tracert 末跳 RTT**。

### ⚠️ 两个必须知道的坑

**坑 1：开着代理/TUN 时，测出来的全是假的。**

如果你的代理软件开了 TUN 模式（v2rayN / Clash 等），所有 TCP 流量都被代理节点接管，
你测到的其实是「**到代理节点**」的延迟，不是到 VPS 的。
实测首尔 VPS 在 TUN 开启时被测成 **2.3ms**，而国内实际访问要 40ms+ —— 完全误导。

工具会检测并**明确警告**。测之前请先关掉代理。

**坑 2：ICMP ping 不可信，认 tracert。**

有些软件会伪造 ping 应答（实测输出 `time<1ms TTL=64`，TTL=64 说明数据包根本没离开本机）。
**tracert 走的是 TCP SYN，ICMP 劫持不了它**，所以以 tracert 末跳 RTT 为准。

## 六、完整采购流程

```
① 快速体检所有候选            → 跑分「全部快速体检」，1 分钟，砍掉明显差的
       ↓
② 本地侧延迟测试              → 关代理，跑 local_speedtest.py，看末跳 RTT 和跳数
       ↓
③ 标准跑分 + 低优先级         → 只对进入决赛的机器跑，看 CPU 单核分和磁盘深度性能
       ↓
④ 完整评估（买之前必跑）       → 路由追踪 + IP 质量 + 流媒体解锁
       ↓
⑤ 晚高峰复测（20:00–23:00）   → 超售机器白天好看、晚上崩，这一步能验出真相
       ↓
⑥ 下单
```

### 第 ⑤ 步为什么不能省

超售（overselling）是指商家卖出 1 核却塞了 5 个用户。表现是：

- 白天没人抢 → 性能正常
- 晚高峰大家都抢 → 你的 CPU 被抢走、IO 排队、带宽被 QoS 限速

**单次跑分完全看不出超售** —— 你得在**高峰时段**跑一次。
建议至少在晚高峰跑 3 次，取最低分那个做参考。

## 七、常见问题

**Q：跑分会不会把机器搞挂？**
不会。快速体检档只读 `/proc` 和做几次小文件读写。标准档有 fio 压测，用的是低优先级模式。
唯一需要注意的是完整档的 iperf3 会打满带宽 —— 勾了「低优先级」就会自动跳过。

**Q：分数比我预期低很多，是不是被坑了？**
先看**可信度**。低于 100% 说明有维度是估算的，标准档才有完整数据。
另外先确认延迟分组里的「国内组」是不是被 anycast 节点带偏了。

**Q：为什么每台机器的「已跳过」文件数都一样？**
那不是下载功能的问题 —— 那是下载浮窗里的统计，「已跳过」是**扫描阶段一次性算出的过滤文件总数**
（`node_modules`、`venv`、`.git` 之类），不会随下载进度变化。

**Q：跑分结果会保存吗？**
会。每次跑分存一份 JSON 到本机数据目录，侧边栏「跑分评估」页能看到历史，
可以对比同一台机器不同时间的表现 —— 这对判断超售特别有用。

**Q：能不能看和别的机器的对比？**
侧边栏「跑分评估」页就是横向对比表。
