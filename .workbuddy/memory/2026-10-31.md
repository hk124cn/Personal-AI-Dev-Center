## 修下载浮窗的裸 i18n key + 写跑分采购指南

### 用户报障：截图里浮窗显示 `15000 sync_files_done`

**根因**：`sync_files_done` 这个 key **在 I18N 表里根本不存在**，
而 `t(key)` 在缺 key 时**静默返回 key 本身**，不报任何错 —— 所以界面直接显示裸 key，
而且**一整天没人发现**（用户截图报障才暴露）。

同一批还缺 4 个：`sync_batches_unit` / `sync_batch_n` / `sync_batch_ok` / `sync_batch_fail`
（所以日志行显示成 `sync_batch_n 15/34 sync_batch_ok`）。

### 修复

1. 补齐 5 个 key
2. **`t()` 缺 key 时 `console.warn('[i18n] 缺少文案 key:', key)`** —— 原来完全静默
3. stats 文案改成带总数：`已下载 15000 / 20147 个文件` + `55591 已跳过`
   （原来只有裸数字 + 坏 key）

### 新增两个常驻回归（`run_checks` 现在 17 项）

- **`tools/test_i18n_keys.py`** —— 扫 `t('xxx')` 调用 vs I18N 表，缺失必须为 0。
  ⚠️ 两个正则陷阱（都踩过）：
  - key 可以**一行写多个**（`wd_mon:{...}, wd_tue:{...}`）→ 不能要求 key 在行首
  - `t('div')` 会误匹配 `createElement('div')` → 需要负向前瞻 `(?<![A-Za-z0-9_])`
- **`tools/test_sync_stats.py`** —— 用真实 SSE 事件形状喂前端的 stats 渲染逻辑，
  断言不出现裸 key + 带总数 + 已跳过数正常

### 写这个测试时踩的坑（Chrome 无头）

1. **`--dump-dom` 只序列化 DOM，JS 变量取不到** → 结果必须写进 DOM 元素才能 dump 出来
2. **变体页会一直轮询后端** → 不加 `--virtual-time-budget` 的话 `--dump-dom` 永远等不到
   "页面稳定"，实测卡死 120s 超时
3. **注入脚本放 `</head>` 前执行会有两个致命错**：
   - `document.body` 还是 `null` → `appendChild` 抛 TypeError
   - 主脚本里的 `const I18N` 此刻处于 **TDZ（暂时性死区）**，
     **`typeof I18N` 会抛 ReferenceError**（typeof 只对 *undeclared* 变量安全，对 TDZ 不安全）
   → 整个注入逻辑必须包在 `window.addEventListener('load', ...)` 里
