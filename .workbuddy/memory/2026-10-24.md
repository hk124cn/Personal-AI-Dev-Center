## VPS 跑分 / 采购评估模块（v1.4.25，用户为黑五采购准备）

### 需求原点

用户原话：「现在对一台VPS测试评价，有哪些专业的网站或者工具？」
→ 后续：「好的，加一个，还有，能测试速度的，可以吗。或者我们单独做一个网页，调用。？
就是不知道需要的数据这些好不好获取，最后能给出各项得分，总分最好。
因为我最近想着黑五，要不要入手一台VPS的，所以产生了这个需求」
→ 「好的，做，还要加个「低优先级」模式。」

### 架构决策：集成进主项目，不单独做网页

理由：SSH 密钥 / 服务器列表 / 监控基线全在主项目里，拆出去要重造一遍且数据割裂。
跑分本质是「给某台服务器做体检」，天然挂在服务器实体上。

### 三个新模块

| 文件 | 职责 |
|---|---|
| `backend/bench.py` | SSH 采集。三档 profile + 低优先级模式 + 分组延迟 |
| `backend/bench_score.py` | 评分引擎。原始值 → 0-100 分 + 总分 + 维度分 |
| `tools/local_speedtest.py` | **本地侧**测速（你 → VPS 的真实延迟），带代理检测 |
| `tools/test_bench_score.py` | 59 项回归，已并入 `run_checks.py`（现 14 项） |

### 三档 profile

| 档 | 耗时 | 内容 | 依赖 |
|---|---|---|---|
| quick | ~15 秒 | /proc + dd + socket，零依赖 | 无（任何 Linux 都能跑） |
| standard | ~10 分钟 | YABS 全套（fio + sysbench + iperf3 + Geekbench） | curl/wget（YABS 自动下二进制） |
| full | ~15 分钟 | standard + NextTrace 路由 + IP 质量 + 流媒体解锁 | 同上 |

### 低优先级模式（用户明确要求）

`nice -n 19` + `ionice -c 3` 包裹执行 —— **这两个会被子进程继承**，所以 fio/sysbench 全自动降权。
另外低优先级下**跳过 iperf3**（YABS `-i`）：iperf3 会打满带宽，nice 管不住；
改用 quick 档的轻量限速下载代替。

### 评分模型

维度权重参考 **VPSBenchmarks 官方 v2026.04 指标权重表**：
CPU 30% · 磁盘 25% · 网络 20% · 内存 15% · 稳定性 10%。

**关键取舍**：VPSBenchmarks 的分是**相对分**（全库百分位，top18%=A），我们没有那个库，
所以做**绝对分**（行业实测阈值校准）。阈值全部可在 `config.json.bench_thresholds` 配置。
主指标用 **Geekbench 6 单核分**（跨机标准化好），sysbench 只作辅助 ——
因为 sysbench events/s 强依赖 `--cpu-max-prime`（10000 vs 20000 差 2 倍），
不同来源的「参考值」不在一个量纲上，拿它当主指标会误导。

### 真踩的坑（都已在代码里注释 + 回归锁定）

1. **`timeout %d` 没做格式化** —— 本文件是 Python 字符串不做 `%` 格式化，远端执行的是
   `timeout %d`（参数非法→立即失败→**假延迟 3ms**）。改成占位符 `__TSEC__` 替换。
2. **dd 输出格式两种** —— 新版 coreutils 是 `copied, 0.17 s, 390 MB/s`（直接给速度），
   旧版是 `in 0.17 s`。之前只匹配旧版 → 磁盘全 None。正则两种都认。
3. **反向指标算反了** —— CPU 抢占率 0%（完全没被抢）被判 0 分！
   `score_value` 现在自动识别「首项得分 > 末项得分」= 越小越好，走反向插值。
4. **延迟必须分组，不能混算** —— 腾讯云首尔那台到 1.1.1.1 anycast 只要 4ms（它在首尔），
   但到国内 119.29.29.29 要 41ms。混算中位数会给出「4ms 满分」的假象。
   → 分 D（国内）/ I（国际）两组，各算中位数，**评分用国内组**。
5. **YABS JSON 空值 bug** —— 偶尔输出 `"ram":,`（键后直接跟逗号无值），标准解析器直接报错。
   `fix_yabs_json()` 用正则补 null + 去尾逗号。
6. **quick 档指标没提升到顶层** —— 磁盘/网络维度整块算不出来（可信度仅 25%）。
   `extract_metrics()` 把 raw 里的字段提升到顶层。
7. **采集层与 API 层 phase 撞名** —— 两层都发 `phase='done'`，前端先收到一个没有分数的假 done。
   采集层统一改成 `phase='progress'`。
8. **内存容量项 IndexError** —— `items[-1]` 取值但项没入列。改用 `add()` 的返回值。
9. **iperf 单位** —— YABS JSON 的 recv/send 就是 **Mbit/s**，我多除了一次 1000（950→0.95）。
10. **topbar 标题竖排** —— `.topbar-left` 是 flex，长副标题把 title 挤成竖排。
    修 CSS：`topbar-left{min-width:0;flex:1}` + `title{white-space:nowrap;flex-shrink:0}` +
    `sub{text-overflow:ellipsis}`。这是通用隐患，任何长文案都会触发。

### ⚠️ 最重要的认知：服务器侧延迟 ≠ 用户侧延迟

服务器侧测的是「**这台机器 → 各公共服务**」的延迟，反映**它的出口网络质量**。
用户采购决策要看的是「**你从家 → 这台机器**」的延迟 —— **两回事**！
阿里云成都的机器到自家 DNS 只要 5ms，但它从国内被访问可能是 40ms。

所以做了 `tools/local_speedtest.py`（在**用户本地**跑），且踩了两个大坑：

- **ICMP 不可信**：本机 ping 被某软件**伪造应答**（实测 `time<1ms TTL=64`，TTL=64 是 Windows
  默认值 → 数据包根本没离开本机）。用 `tracert`（走 TCP SYN，ICMP 劫持不了）才准。
- **代理/TUN 会让所有测量变成假的**：实测开着 v2rayN TUN 时，首尔 VPS 被测成 **2.3ms**
  （真实从国内过去 40ms+）—— 那测的是**到代理节点**的延迟。
  工具现在会检测环境变量代理 / Windows 系统代理 / TUN 虚拟网卡并**明确警告**。

## 首页快速操作加「跑分」入口 + 批量跑分面板

用户要求：「把「跑分」按钮也加到首页快速操作里」。

### 为什么不只加个跳转按钮

首页快速操作区是「单一动作」型按钮（新建项目 / 添加服务器）。只加个跳转到「跑分评估」页的按钮
价值有限（少一次点击而已）。真正解决痛点是「扫 N 台要点 N 次」，所以做成**批量跑分面板**：
- 弹窗列出所有服务器，每行：名称 + IP + 当前分数 + 单台「跑分」按钮
- 顶部「**全部快速体检**」按钮 → **串行**跑完所有台（15 秒/台）
- 串行而非并发：并发会同时开多个 SSH + 多台机器同时跑 dd，机器和本机都抢资源
- 新增 `benchRunOnce(sid, profile, lowPrio)`：把 SSE 封装成 Promise，供批量串行 await

### 实测

- 批量 API 实测：2 台串行 110 秒，0 失败（阿里云 56.9 / 腾讯云上海 61.5）
- 视觉验证（Chrome 无头变体页）：首页按钮位置正常、批量面板 4 行渲染正确
- 回归 14/14，换包校验 30/30

## 🐛 跑分弹窗「连接中断」事故（2026-10-25，用户截图报障）

### 症状

用户所有服务器点「开始跑分」都显示「**连接中断（后端可能已退出）**」。

### 根因：EventSource 只能发 GET

我用了 `new EventSource(url)` 连后端的 **POST** 路由 `/api/bench/{server_id}`。
**`EventSource` 规范只允许 GET** → 浏览器直接拒绝 → 立刻 `onerror` → 界面显示连接中断。

**为什么所有测试都绿**：
- 后端 API 测试：用 `urllib.request.Request(method='POST')` 手动发 POST → 当然通
- 静态检查：JS 语法没问题 → 通
- 截图验证：只截「初始态」和「结果态手动构造」的 DOM → 没真点过按钮

**只有真浏览器点一次按钮才暴露。**

### 修法

改成项目里已有的套路（下载/上传进度就是这么干的）：
`fetch(url, {method:'POST'})` → `res.body.getReader()` → `TextDecoder` 流式读 SSE。
抽出通用函数 `benchStreamSSE(url, {onEvent, onError})`，`benchRun()` 和 `benchRunOnce()` 共用。
取消逻辑从 `es.close()` 改成 `ctl.abort()`（`_benchState.es` 现在存的是 AbortController）。

### 新增回归测试 `tools/test_bench_browser.py`（11 项，已并入 run_checks → 15 项）

真实 Chrome 无头 + **真点「开始跑分」**，两层验证：
- **前端层**：把步骤轨迹累积写进 `document.title`，断言走到了 GOT_START（收到后端 start 事件）
  → 老 bug 下 EventSource 被拒，连 start 都收不到
- **后端层**：断言 `benchmarks/` 目录**新增了结果文件**，且内容含 CPU 型号 / 磁盘速度 / 延迟分组
  → EventSource 被拒时后端**根本收不到请求**，不会新增文件

### 写这个测试时踩的坑（都是"验证方法"本身的坑）

1. **`--dump-dom` 的 DOM 断言是假阳性** —— 它会把 `<script>` **源码**也序列化进 DOM，
   所以源码里的 `"bench-ring"` 字符串会被误判成"已渲染"。必须用**真实 DOM 查询**
   （`document.querySelectorAll('.bench-ring').length`）并通过 title 传出来。
2. **注入脚本里 `let` 声明的变量不在 `window` 上** —— `window._benchState` 是 undefined，
   必须直接引用 `_benchState`（同一全局词法环境）。
3. **注入脚本的一个括号没闭合 → 整个 script 块不执行** → title 一直是默认值。
   `py_compile` 只查 Python，查不出 JS 错。
   → **验证注入块要用 `node --check`**（且要先剥掉 `<script>` 标签，node 不认 HTML）。
4. **Chrome dump 完就退出会掐断 SSE** → 后端生成器中断 → 跑分不落盘。
   要让 Chrome **保持存活**：用 `--remote-debugging-port=9222`（不截图、不 dump、不设 virtual-time）
   启动，然后 Python 侧轮询 `benchmarks/` 目录。
5. **步骤只留最后一步会丢证据** → title 要**累积**（`__steps.join('>')`），
   并且相同内容不重复 push（否则 title 爆炸到几千字符）。
6. **虚拟时间下 `setInterval` 飞快跑** → 计数器很快耗尽，轮询提前停 → 改用真实时间轮询。
