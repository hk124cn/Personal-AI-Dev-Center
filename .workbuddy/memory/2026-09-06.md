# 2026-09-06 LLM 分析诊断 + 简介回填（A/B 双改）

## 背景（用户问）
用户问「同步后不启动 AI 分析更新项目简介吗」——确认：同步内建 `apply_llm_analysis` 会自动跑 LLM（若启用+key有效），产出 `llm_summary`（前端「LLM 摘要」）。用户要求两件事都做：
- A：把 `llm_summary` 回写到项目 `desc`（简介）字段；
- B：排查/修复商汤 `api_failed` 黑盒问题。

## 关键事实（查证）
- 商汤配置：provider="商汤科技" → `call_llm_api` 走 `else` 分支 `_call_openai`（OpenAI 兼容）。`base_url=https://token.sensenova.cn/v1` 经验证是**官方正确端点**（`POST /v1/chat/completions`），model `sensenova-6.7-flash-lite` 会被重定向到 6.8，返回标准 `choices[0].message.content`。**端点/模型/解析都没问题**，所以之前的 api_failed 来自 key/额度或 JSON 解析失败被吞。
- 项目简介字段名是 `desc`（非 description），前端 2578 行 `escapeHtml(p.desc)` 在详情卡「描述」区渲染。

## 改动
- `backend/llm_analyzer.py`：`_extract_json_from_text` / `_call_anthropic` / `_call_openai` / `_call_qwen` / `call_llm_api` / `analyze_project` 全部改为返回 `(结果dict|None, 错误原因str|None)` 元组；HTTP 错误捕获状态码+响应体，JSON 解析失败返回具体原因（不再静默 None）。
- `backend/sync.py`：`apply_llm_analysis` 接收 `llm_error` 写入 `remote_data["llm_error"]`；sync_single/sync_all 的 `project_entry` 增加 `llm_error`；**新增 desc 回填**：`llm_summary` 非空且项目 `desc` 为空时，写回 `desc` 并 `save_config`（sync_all 末尾统一 save）。
- `backend/app.py`：/api/analyze 路由解包元组，错误带 `llm_error` 进 entry。
- `backend/test_llm.py`：两处 `call_llm_api` 调用解包元组。
- `index.html`：3 处数据合并加 `_llmError`；详情卡 LLM 状态行追加显示错误原因；回填的 `desc` 已在 2578 行展示。
