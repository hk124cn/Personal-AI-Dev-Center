## exe 显示「满屏 CSS 代码」的根因与修复（用户实测报错）
- 现象：双击 `dist/Personal-AI-Dev-Center.exe`，Electron 窗口打开但满屏 CSS 源码。
- 根因：`backend/app.py` 的 `serve_frontend()` 原用 `FileResponse(str(index))` 未声明 media_type；PyInstaller 打包后的 Windows 环境里 `mimetypes.guess_type()` 猜错 `.html` 类型，浏览器把 HTML 当纯文本/CSS 渲染。
- 修复：`FileResponse(str(index), media_type="text/html")`。提交 `6cafe3b`。
- 真实 Electron 启动链路无 bug：`main.js` 的 `startBackend()` 注入 `DEV_CENTER_RESOURCE_DIR=process.resourcesPath`（= resources/ 绝对 Windows 路径，含 index.html），所以真机 GET / 既能找到 index.html 又返回 text/html → 页面正常。用户截图是「CSS代码」而非 404，已间接证明真机 index.html 能被找到。

## 测试打包 exe 的三个假阴性（务必避开，否则误判）
1. **8765 被孤儿 PyInstaller exe 进程占用**：one-file exe 解压后实际监听 8765 的是内层 python 进程，`kill $SV`（bash 外层 PID）杀不净 → 后续测试请求全被僵尸进程响应（它没注入 env → 返回 Frontend not found）。排查：`Get-NetTCPConnection -LocalPort 8765 -State Listen` 找真实 PID，`PowerShell Stop-Process -Id <pid> -Force` 清掉（保留 WorkBuddy 主进程 13876）。
2. **curl -I 发 HEAD 到只注册 GET 的路由 → 405**：路由只 `@app.get`，curl -I 用 HEAD 被拒（allow: GET）。要看 GET 真实响应头（含 Content-Type）须用 `curl -s -D - -o /dev/null http://localhost:8765/`。
3. **git bash 启动 Windows exe 时 env 可能不传递**：直接 `export X=... && .exe &` 在 git bash 下 env 不一定进 Windows 原生 exe，导致打包 exe 退回 _MEIPASS 找不到 index.html。验证路径解析改用 `python -c "from backend import common_paths; print(...)"` 复现（已确认逻辑正确），或信任真实 Electron 注入。
