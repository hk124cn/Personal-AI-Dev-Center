# 2026-10-27

## 新增服务器接入：不需要在远端装任何东西

### 用户提问

> 「我新增了一台服务器，是不是只要把密钥传上去后，就可以自动监测了，还是说需要你登录上去构建脚本？」

### 结论（架构层面）

**不需要登录上去构建脚本。** 本项目是「**SSH 裸命令**」架构 ——
监控 / 项目同步 / 跑分 / 计划任务全是直接跑 shell 命令，远端**零安装**。

| 功能 | 远端要求 |
|---|---|
| 主机监控 | 无（只读 `/proc/stat`、`/proc/meminfo`、`/proc/net/dev`、`df`、`/proc/loadavg`、`nproc`、`uname`） |
| 项目同步 | 无（tar-over-SSH，**服务器端零写入**） |
| 跑分 quick | 无（`/proc` + `dd` + bash `/dev/tcp`） |
| 跑分 standard/full | 需能访问 yabs.sh / nxtrace.org（curl 或 wget 二选一） |
| 计划任务 | 需能改 crontab（对应权限） |

### ⚠️ 概念澄清：**私钥留本机，只传公钥**

用户说「把密钥传上去」时方向可能是反的：
- **私钥永远留在本机**（`config.json` 的 `key_path` 指向本机 `~/.ssh/xxx`），**绝不上传到服务器**
- 上传到服务器的是**公钥**（`.pub`），放进服务器 `~/.ssh/authorized_keys`
- 公钥一通 → 上面全部功能自动可用

### 本次实际故障

新增「阿里云海外_新加坡」后监控报 `SSH 连接失败: Authentication failed`。
诊断（paramiko 逐台验证）：现有 4 台免密正常（0.8–2.2 秒），唯独新这台
`AuthenticationException`；系统 ssh 报 `Permission denied (publickey,password)`
→ **服务器可达、SSH 正常，只是公钥没进 authorized_keys**。

### 修好的 `deploy_key.ps1`（原有 3 个真 bug）

1. **读错配置文件** —— 读的是仓库根的 `config.json`（**旧结构、服务器列表已过期**），
   而后端读的是 `%APPDATA%/Personal AI Dev Center/config.json`。
   → 改成优先 APPDATA，回退仓库根。
2. **硬编码私钥 `<key>`** —— 但 GCP 那两台用的是 `id_ed25519`，
   公钥/私钥对不上。→ 改成**每台用 config 里配的那把私钥**（`key_path`/`sshKey`），
   公钥从对应私钥的 `.pub` 取（没有就用 `ssh-keygen -y` 导出）。
3. **字段名不兼容** —— 新结构 `host/port/user/key_path` vs 旧结构 `ip/sshPort/sshUser/sshKey`
   → 加 `Get-Field` 兼容层。

### PowerShell 脚本踩的坑

1. **`$host` 是只读自动变量**（= `InternalHost`）！
   我把变量命名成 `$host_` 并在字符串里写 `$host` → 输出全是
   `System.Management.Automation.Internal.Host.InternalHost`。
   → 一律用 `$sshHost`。
2. **check 步骤必须带 `-i $keyPath -o IdentitiesOnly=yes`** ——
   否则 ssh 会去试 agent 里的其它密钥，用错身份就认证失败，
   **把能免密的机器误判成「连不上」**（阿里云成都/腾讯云上海都中招了）。
3. **verify 步骤必须加 `StrictHostKeyChecking=accept-new`** ——
   否则首次连某台机器时 ssh 弹「Are you sure you want to continue connecting?」→ **卡死**。
   （阿里云成都过了是因为它的 host key 早就在 known_hosts；腾讯云上海没记录 ——
   Paramiko 用 AutoAddPolicy 不写 known_hosts → 卡住。）
4. **`BatchMode=yes` 避免密码提示卡死** —— 非交互环境下 ssh 会等密码输入直到超时。
   → check / 免密尝试都用 BatchMode=yes；只有真正需要写公钥时才走密码交互。
5. **要区分两种失败**：
   - `Permission denied / publickey` → **主机是通的**，只是公钥没部署 → **继续走密码部署**
   - `Connection refused / timeout` → 主机不可达 → 真失败

   （原来一律判 FAIL，导致「公钥未部署」这个最常见的场景反而没法自动修。）
6. **Windows 执行策略默认禁止跑 .ps1** → 要用
   `powershell -ExecutionPolicy Bypass -File .\deploy_key.ps1`。
7. 从 Bash 调 `powershell -Command` 会被安全策略拦（"Invoking PowerShell from Bash
   bypasses PowerShell security checks"）→ 改用 PowerShell 工具。

### 新增参数

- `-Name <关键词>`：只处理匹配的服务器
- `-DryRun`：只看要做什么
- `-Force`：忽略「公钥已存在」
- `-Batch`：只处理能免密连接的（CI 用，绝不卡密码提示）

### 新增服务器的标准流程

```powershell
cd "D:\app\Personal AI Dev Center"
powershell -ExecutionPolicy Bypass -File .\deploy_key.ps1 -Name 新加坡
```
（输一次 root 密码 → 写公钥 → 自动验证免密）

备选：用云厂商控制台的 VNC / Workbench 登录，手动把
`~/.ssh/<key>.pub` 的内容追加到 `~/.ssh/authorized_keys`（权限 600）。
