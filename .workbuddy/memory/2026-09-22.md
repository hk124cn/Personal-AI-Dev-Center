## 调查（只读实测，未改任何代码）：定时同步到底干嘛 + AUTO-STOCK 全量下载的代价

用户三问：①定时同步现在有什么作用？②AUTO 项目有几万子文件，全下载是不是很久、会不会影响其他任务、占多少资源？③好好调查。

### ① 定时同步的作用 —— 只「读文字」，从不下载文件

- `scheduler.py:113 run_schedule()` → 只调 `sync_all()` / `sync_single()`。
- `sync_all` 对每个项目只跑 `find <remote_path> -maxdepth 1 -name '*.md'`（`sync.py:463-465`），
  解析 TODO/PROGRESS/ISSUES + 通用 md 摘要，可选 LLM 分析 → 写 `data/latest.json`。
- **子目录一个都不进** → AUTO-STOCK 那 9.5 万个文件跟定时同步**毫无关系**。
- 作用范围：首页卡片、项目详情的 todos/进度/技术栈/LLM 摘要、预警。**不产生任何本地文件。**
- 也不会写项目的 `lastUpdate`（那是另一个缺陷，见 `2026-09-21.md`）。
- 时间开销：昨天那次 16 个项目共 `duration_sec=845.9`（14 分钟），大头是 LLM 分析
  （AUTO-STOCK 单项目 84s，它只读了 9 个 md）—— 慢在 LLM，不在文件数。

### ③ 实测传输速率（tar-over-SSH 读流，不落盘）

用 app 自己的 `_remote_stat_tree_fast` 拿清单，再走 `tar --null -cf - -C <dir> -T -` 读流计数：

- 171.7 MB / **175.3 秒** → **0.98 MB/s，约 13 个文件/s**
- 分片可见规律：前 110s 只走了 70MB（小文件为主，RTT 拖死），
  116~144s 突然 3MB/s（在传 reports/ 里的大文件）→ **瓶颈是小文件 + 跨境 RTT，不是带宽**。
- 外推：默认过滤 ≈ **2 分 55 秒**；全量 95,380 文件按文件速率 ≈ 127 分钟，
  按字节速率 ≈ 52 分钟 → 合理区间 **1~2 小时**。

> ⚠️ 用户人在日本、服务器在成都/国内云 → 跨境 RTT 是主要成本（每个小文件要几个来回）。

### ④ 资源占用与并发影响（代码定位）

- 下载路由 `app.py:798 /api/sync-download/{project_id}`：起 **daemon 线程** + `queue` + **SSE** 推进度，
  可 `POST /api/sync-download-cancel/{id}` 取消（`_DOWNLOAD_CANCEL` 带 `_cancel_lock`）。
- **不抢 `_write_lock`**（那只在 `save_config` 用，app.py:328）→ 不会挡住改配置。
- 传输是 `tarfile.open(fileobj=stdout, mode='r|')` **流式解包**，逐文件 `read(262144)` 写盘 →
  **内存不随包大小增长**；内存里只有文件树 dict + 清单 payload（9.5 万条约几 MB，可接受）。
- 防护齐备：路径穿越过滤、`os.utime` 保留 mtime、stderr 后台排空防死锁、网络中断自动重试 1 次。
- 会互相影响的点：①与同服务器的其他同步抢出口带宽（AUTO-STOCK 与「小龙虾」同在 `ali`）；
  ②Python 单线程读写循环有 GIL 争用（轻微）；③服务器侧 `tar` 单进程占 CPU + 磁盘 I/O。
- 本机磁盘：D: 剩 **275 GB**（够，但要留意 `D:/local` 已有 3 个 AUTO-STOCK 备份目录
  43,433 / 38,294 / 43,925 个文件 + 3 个 tar.gz 共约 1.5 GB —— 那是用户自己的历史备份）。
- `AUTO-STOCK` 的 `local_path = D:/local\AUTO-STOCK` **目前不存在**（还没下过）。

### 结论（给用户的建议）

1. 想本地留一份源码/文档 → **默认口径直接下**，3 分钟以内，不用纠结。
2. `all=true`（连 `venv/`、`data/`、`logs/` 一起拿）→ 1~2 小时 + 3GB，
   而 `venv/` 本地重建即可、`data/`+`logs/` 是运行时产物，**基本没必要下**。
   真需要全量，建议服务器上先 `tar` 成一个包再单独取（少走 9.5 万次小文件往返）。

### 关键实测（`latest.json` 16 个项目）

- `progress.progress` —— **15 个 `None` + 1 个 `0`** → `mergeAPIData` 的 `if (apiP.progress.progress > 0)`
  永远不成立 → **进度条 100% 是 config.json 手填值**（70/40/65/100…），同步一次都没覆盖过。
- `todos` / `issues` / `llm_summary` / `llm_tech_stack` —— **全都有数据**（AUTO-STOCK：4 待办、20 已完成、
  5 问题、摘要 215 字、技术栈 14 项）。所以同步其实**干了活**，只是成果全在详情弹窗里，
  首页一个都不显示 → 用户自然觉得「没看到」。
