# 2026-09-21

## 排查（诊断，未改代码）：首页「需要关注」13 项一直显示「内容 105 天未更新」

用户提问原文：**「左边的需要关注，一直没有更新是怎么回事，不是每天有定时更新文档吗？是不是可以算作更新？」**

### 结论：这个数字**不是内容陈旧度**，也**跟同步无关**

它读的是 `config.json.projects[].lastUpdate` —— 一个**只在「新建/编辑项目」弹窗保存时被写成当时时刻**的字段
（`index.html:3662 / 3698 / 3706`，全是 `new Date().toISOString()`）。105 天 = `2026-06-08T13:40:37Z`，
就是那批项目记录最后一次在面板里被保存的时间。

### 证据链

| 环节 | 实际数据 |
|---|---|
| `latest.json.last_sync` | `2026-09-20T12:00` 起跑，`16/16 success`，`source="每周日12点同步所有"` |
| 定时任务（`config.json.schedules`） | **只有一条**，`freq=weekly, weekdays=[6], run_time=12:00` → **每周日一次，不是每天** |
| `latest.json.projects[*].progress.last_update` | 16 个项目**全为空**（`None` 或 `""`） |
| `config.json.projects[*].lastUpdate` | 15 个项目全有值，最旧 `2026-06-08`（105 天）、最新 `2026-07-30`（53 天） |
| 侧栏计数 13 | = 15 个项目 − 2 个 `paused`（`computeAlerts` 只收 `active`/`dev`）✅ 与截图吻合 |

断点：远端**没有 `PROGRESS.md`** → `parse_progress_md` 拿不到 `最后更新: xxx` 行 → 值为空 →
前端 `mergeAPIData()` 只在 `if (apiP.progress.last_update)` 为真时才覆盖 `local.lastUpdate`
→ **空值就保留 config.json 的旧值** → 预警永远不消除。

### ⚠️ 踩到的判断陷阱：别用 `latest.json` 的 `md_files` 判断文件是否存在

`sync.py:475-482` 会**乐观地把 `TODO.md` / `PROGRESS.md` / `ISSUES.md` 三个名字塞进 `md_files`**，
即使 `find` 根本没找到。所以 AUTO-STOCK 的 `md_files` 里明明列着 `PROGRESS.md`，
但 `progress` 字段是 `None`（`cat` 报 No such file，走到 line 539 的分支）。
**判存在性要看解析结果字段，不看 `md_files` 清单。**

### 可用素材：`remote_mtime` 才是现成的「内容时间」

每个项目条目都有 `remote_mtime`（`sync.py:545-554`，对项目目录跑 `stat -c %Y`），实测有值且合理
（AUTO-STOCK 9-09=12 天、亚马逊竞价 5-05=139 天…）。
⚠️ 但它是**目录本身**的 mtime —— 只在目录项增删改名时变，**改已有文件内容不会动它**。
要当「内容更新时间」用，得改成取目录内**最新文件的 mtime**（`find ... -printf '%T@\n' | sort -rn | head -1`）。
另：3 个项目（auto-claw.cn 展示网页 / 文件管理系统 / 空名那条）返回 `1970-01-01`，即 `stat` 返 0，路径有问题，可顺带查。

### 给用户的三个选项（等其选择，未动手）

- **A（推荐）**：后端同步时算「目录内最新文件 mtime」→ `/api/data` 返回新字段 → 前端 `lastUpdate` 以它为准。
  全自动、不需要人工维护 Markdown；代价是改 `sync.py` + `index.html` 并重打包（约 8~12 分钟）。
- **B（零改代码）**：在各远端项目根放 `PROGRESS.md` 并写 `最后更新: 2026-09-21`（正则 `最后更新[：:]\s*(.+)`）。
  下周日同步即可刷新；缺点是靠人工维护、过阵子又会陈旧。
- **C**：把「同步成功」也算作更新 —— **不推荐**，等于让预警永不触发、彻底失效。

关于用户问的「是不是可以算作更新」：**不能**。两个时间正交是既有设计（知识库《区分内容更新时间与同步刷新时间》）。
真正该修的是「内容时间**没有数据源**」，不是让它去抄同步时间。
