### 三、改写历史（filter-branch）

**第一次尝试失败**：`--tree-filter` 跑 80 个 commit 超时被 SIGTERM（预测 80×4.5s，实测远超）。
→ 换 **`--index-filter`**（不 checkout，直接改 index 里的 blob），80 个 commit 约 6 分钟。

**index-filter 关键点**：
- 先 `git cat-file blob | grep -q` 判断**是否真含敏感值**，只重写命中的 blob
  （否则 sed 会改动所有文件的行尾，导致全库 diff 噪音）
- `git hash-object -w --stdin` 生成新 blob → `git update-index --cacheinfo "$mode,$NEW,$path"`
- `--msg-filter` 也要做替换（commit message 里可能也有）
- `--prune-empty --tag-name-filter cat -- --all`

**踩到的 sed 转义坑**：含反斜杠的路径规则 **没生效** ——
sed 正则里 `\y` 是未定义转义（被当字面 `y`），所以 `D:\` 开头的路径匹配不到。
→ 改用 `.` 通配（`.` 同时匹配 `\` 和 `/`），替换文本统一用正斜杠。

**改写后**：HEAD SHA `96e8f69` → `4131664`，完整历史（80 commit / 36617 行 diff）扫描 **0 命中**。
