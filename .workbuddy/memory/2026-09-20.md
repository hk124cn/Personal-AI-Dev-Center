## 知识库归档：本轮经验固化成 5 篇

### 做法：走应用自己的接口写，别手写文件

`POST http://127.0.0.1:8765/api/kb/doc`（**app 当时在运行**）。好处是后端
`kb_save_doc()` 自己负责 `_kb_slug()` 生成文件名 + `_kb_build_md()` 生成前言，
格式一定对得上：

- 前言字段：`title` / `category` / `tags` / `author` / `created` / `updated`
- `tags` 是 **JSON 数组**，必须合法（解析用 `json.loads`）
- 文件名 = `_kb_slug(title)`（非 `\w`、非中文的字符全换成 `-`，再转小写）
- 带 `id` 提交 = **原地更新**：`created` 保留、`updated` 刷新（实测更新既有文档后
  `created=2026-08-01T16:25:00` 原值保留 ✅）

## ⚠️ 发现一个既有缺陷（**没有擅自改**，等用户定）

有 **3 篇**文档的前言把 title/author 写成了**带双引号**：

```
title: "个人资产模块：四类实体与主从（外键）关联建模"
author: "ai"
```

分别是：`个人资产模块-实体关系与主从建模`、`服务器计划任务-cron管理`、
`便携版启动问题-taskkill自杀根因与只检测提示修复`。

而 `_kb_parse_frontmatter()` 是 **quote-naive** 的（只做 `line.split(':', 1)` + `strip()`，
**不剥引号**），于是 `/api/kb/docs` 返回的标题和作者**带着引号**：

```
["开发文档"] "个人资产模块：四类实体与主从（外键）关联建模"   author="ai"
[运维笔记  ] 实时测速（TCP 端口探测）实现说明              author=ai     ← 没引号的是对的
```

→ 界面上这 3 篇的标题会显示成 `"个人资产模块：…"`，作者会显示成 `"ai"`。
后端自己的 `_kb_build_md()` 写出来的是**无引号**，所以 13 篇里 10 篇正常。

**修法**：把那 2 行的引号去掉即可（纯机械，不动正文）。属于用户内容，没擅自动手。
如果哪天真要根治，应改 `_kb_parse_frontmatter()` —— 解析时把首尾成对的引号剥掉，
这样以后怎么写的都能兼容。

## 经验小结

- **写知识库一律走 `/api/kb/doc`**，手写文件容易在前言格式上出岔子
  （上面那 3 篇的引号问题八成就是早期手写或旧前端留下的）。
- 归档经验时优先写「**现象 → 根因 → 修复 → 验证 → 教训**」结构，
  和知识库里既有文档的体例保持一致。
- 值得进知识库的判据：**换个人接手会重新踩一遍的坑**。
  一次性的排障过程不必写（那些留在 `.workbuddy/memory/` 日记里就够）。
