## 🔥 electron-builder 构建死锁坑（高优先复用）
- 现象：两次 `npm run build`（portable）在解包完成后、**单文件压缩(pack)阶段死锁**——`win-unpacked` 时间戳停住、进程空转数小时、零磁盘活动。不是慢，是真挂。
- 根因：多半是 **Defender 扫那个 ~21MB 后端 onefile exe 把压缩进程锁死**，叠加**构建前残留的 node/electron 孤儿进程或 live app 占着 dist 文件锁**。
- 解法（构建前必做）：
  1. `taskkill /f /im node.exe` + `taskkill /f /im electron.exe`（杀**所有**构建进程，不要只杀快照里几个 PID——会有漏杀子进程，且旧 `win-unpacked` 删不掉）。
  2. `rm -rf win-unpacked dist_new`（确认真的删掉；若 `rm` 静默失败是句柄未释放，等几秒再删）。
  3. 试加 Defender 排除项：`Add-MpPreference -ExclusionPath 'D:\app\Personal AI Dev Center'`（需权限，UAC 可能卡掉返回空——但加上更稳）。
  4. 干净环境重跑 `NODE_OPTIONS= npm run build` → **2~3 分钟跑通**（对比挂死 4 小时）。
- 构建命令别用 `| tail -40`（会缓冲看不到进度/卡点）；改 `> /d/tmp/build.log 2>&1` 落盘，方便定位死锁行。
- `package.json` 的 portable `artifactName` 构建 Dev 版时临时改 `Personal-AI-Dev-Center-Dev.exe`，**构建完务必还原主力名**（本次净变动为零，说明上一轮已还原）。
- grep 在 Git Bash 里 `\[scheduler\]` 这类转义易误报为 0；要确认就去 `Read` 日志原文（日志里确有 `[scheduler] started`）。
