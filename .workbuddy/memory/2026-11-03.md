## 用户报「没看到超售警告条」→ 根因：版本号没 bump + 警告条位置在结果页

### 根因一：版本号一直是 1.4.26（发布纪律疏漏）

连续几次改动（i18n 修复 / 跑分徽章 / 趋势图 / steal 警告条）**全都没 bump 版本号**，
所以用户启动新版 app 看到的还是「v1.4.26」，跟旧包**完全一样** → 根本看不出更新了。

**已修**：
- bump 到 **1.4.27**（`package.json` + `index.html` 两处；后端 `common_paths.py`
  的 `APP_VERSION` 是**运行时**从 package.json 读，Electron 经 `DEV_CENTER_APP_VERSION`
  注入 → 不用改，但要**重建后端 exe**）
- **`run_checks.py` 加了一条「版本号一致（package.json == index.html）」**检查 → 防再犯

### 根因二：警告条只在「跑分结果页」顶部

不在首页、不在「跑分评估」对比表。而且**用户那台机器 steal = 0%** →
显示的是**绿色「未被宿主机抢占，正常」**，不是红色警告 → **用户自然以为没这功能**。

**真实数据**（阿里云成都，11-02 的记录）：
```
ali_20261102-004745.json   window=0  cum=0  virt=kvm
```
→ 是 **KVM 虚拟化**、steal **真的是 0%** → 结构上没被抢，绿色正常提示是对的。

### 顺带修的 UI 缺陷

警告条原本只写「CPU 抢占率 — 未被宿主机抢占，正常。」，
**中间那个「—」是分隔符，数值根本没显示** → 用户不知道是 0% 还是 0.4%。
已改成 `CPU 抢占率 0.00% — 未被宿主机抢占，正常。`

### 验证方式（这次做对了）

**不要再用「实时跑分 + 等结果」来截图** —— 跑分要 40+ 秒，Chrome 的
`--virtual-time-budget` 在 pending 请求时会**暂停虚拟时间**，dump 会在结果渲染前发生
（实测 `ring=0`，结果态根本没出来）。

✅ **正确做法**：用 `/api/bench/{id}/history` 拿**真实历史数据**，
直接调前端的 `benchRenderResult({result:{raw:...}, score:item.score})` 渲染 → 秒出且稳定。

⚠️ **`--dump-dom` 会把 `<script>` 源码也序列化进 DOM** → 用字符串匹配判断
「元素是否存在」是**假阳性**（第一版验证就栽在这）。
必须先 `re.sub(r"<script[^>]*>.*?</script>", "", dom, flags=re.S)` 剥掉脚本再查。
