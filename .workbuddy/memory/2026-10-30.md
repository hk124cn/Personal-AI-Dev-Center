### 本轮踩到的坑（全是"自己把自己卖了"型）

1. **在记忆文件里写下了脱敏规则本身** ——
   记录「某值 → 某占位符」时把**两边都列出来**，等于把刚清掉的值又请回来。
   扫描报出 5 处命中，拦住了推送。
   → **纪律：写「脱敏记录 / 扫描命中」这类记忆时，示例值本身也必须用占位符**。
   而且这类记忆会让人（包括下一个我）误以为「已经清过了」。

2. **临时脚本里的硬编码检测正则** ——
   `re.findall(r"<真值>|<真值>", body)` 这种检测代码，本身含真值就是泄露源。
   → 检测模式必须**从 config.json 动态构造**；且一次性脚本（`tools/_tmp_*`）
   已在 `.gitignore` 里，用完即删。

3. **GitHub API 不带 User-Agent 会返回 404**（不是 403）——
   跟「资源不存在」长得一模一样。我第一版验证脚本漏了 UA，
   于是旧 SHA 全报 404 → 会得出「清理成功」的**假报告**。
   → 幸好先跑了 `--check` 自检。**任何 GitHub API 探测都必须带 UA。**

4. **改 `packed-refs` 忘保留行尾换行** → `fatal: unterminated line`。
   → 写回要用 `splitlines(keepends=True)`；git 要求每行以 `\n` 结束。

5. **`git rm --cached` 不会清历史** —— 只移出索引，历史里的旧版本照样能被扫出来。
   → 已经进过仓库的东西，必须改写历史或重写那个 commit。

6. **删库重建后首次 push 报 `Permission denied (publickey)`** ——
   但 `ssh -T git@github.com` 通、`git ls-remote` 也通（`Exit status 0`），
   **只是瞬时失败，重试一次就成功**（`[new branch] main -> main`）。
   → GitHub 刚建库后权限同步有延迟，别慌着重配 SSH key。

### 认证路径的经验（重要）

- **GitHub CLI 的 device flow 拿不到删库权限** ——
  OAuth App 的 token 是「应用身份」，GitHub 明确禁止它删仓库（403
  `Resource not accessible by integration`）；而且 GitHub CLI 的 OAuth app
  **不接受自定义 scope 请求**（返回 `scope: None`），申请 `delete_repo` 无效。
  → 删库只能用 **classic PAT**（用户身份），或**用户手动删建**。
- 2FA 验证页会拦 device flow（要求先验证短信/TOTP），但**验证一次就永久放行**。
- SSH key 是**账户级**的，删仓库不受影响 → 手动删建后能直接 push 回去。
