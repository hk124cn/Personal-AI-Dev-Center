## 第 5 项文档对齐 + 实时测速修复（2026-07-26 晚 续）
- **实时测速「阿里云始终超时」根因确认**：`/api/speed-test` 原实现用 ICMP `ping`（Windows `ping -n 2 -w 2000`），而阿里云安全组默认拦截 ICMP → ping 收不到回包 → 后端返回 `error`，前端把任何非 ok/skip 都显示成「超时」。腾讯云/GCP 同理可能被拦。
- **修复：改 TCP 端口探测 + 并行**：`backend/app.py` 的 `speed_test()` 重写为对每个服务器 `socket.connect_ex((host, port))`（port 取 config 的 `port` 默认 22），超时 3s，用 ThreadPoolExecutor 并行（max_workers=8）。绕过 ICMP 拦截（ssh 端口必开），整体耗时从「串行十几秒~30s」降到 ~3s。已用本机回环地址单元测试：skip/error/timeout 状态均正常返回。
- **前端同步改动**（`index.html`）：
  - 实时测速按钮激活时加 `.btn.active` 样式（绿色加粗 + 阴影），关闭时移除 → 满足用户“点击后按钮加重/变色”的要求。
  - `runSpeedTest()` 加 `_speedTesting` 守卫，避免 `setInterval(5000)` 叠加请求堆积（这是“看起来只测了一两次”的另一原因）；前端 fetch 超时 30000→12000ms。
  - 区分 `timeout`（显示「超时」）与 `error`（显示「不可达」）。
- **文档对齐（商汤为默认配置）**：`docs/LLM_ANALYSIS.md`、`docs/QUICK_START.md`、`docs/USAGE_GUIDE.md` 已将推荐提供商改为**商汤 SenseNova**（`provider:"商汤科技"`、`model:"sensenova-6.7-flash-lite"`、`base_url:"https://token.sensenova.cn/v1"`），新增商汤 API Key 获取入口，并**修正不存在的 `python backend/sync.py --project xxx` 命令**为 `python -c "from backend.sync import sync_single; sync_single('xxx')"`。`config.llm.example.json` 的 llm 段也同步改成商汤。
- 注意：后端 speed-test 现在测的是「到 SSH 端口的 TCP 连接延迟」，不再是 ICMP RTT。若用户坚持要纯 ping，需在阿里云安全组放行 ICMP，但 TCP 探测对“能否 SSH/服务可达”更有意义。
