## ⚠️ PyInstaller 坑：本地模块必须用包式导入（本次踩到）
- 第一版后端 exe 运行时报 `ModuleNotFoundError: No module named 'cron_manager'`。`grep -a` 在 exe 里能搜到字符串 `cron_manager`/CronManager，但那是引用不是模块体——**字符串存在 ≠ 模块被打进归档**。
- 根因：cron_manager.py 在 `backend/` 下，而我在 app.py 写成 `from cron_manager import CronManager`（顶层导入）。PyInstaller 配 `--collect-submodules backend`，只收集 `backend.*` 子模块；其他本地模块（sync/common_paths）都是 `from backend.xxx import` 写法才被收集。
- 修复：改为 `from backend.cron_manager import CronManager`（与 sync 一致）。
- 验证手段：不要只 grep，要跑 exe 启动冒烟（隔离 `DEV_CENTER_DATA_DIR` + `timeout` 跑几秒，看是否到绑端口/是否报 ModuleNotFoundError）。注意 8765 被实时 app 占，冒烟会报 "Address already in use" 属正常，能到这步即证明导入成功。
- 教训：FastAPI 后端打 onefile 时，所有 `backend/` 下的本地模块一律用 `from backend.xxx import`，且 PyInstaller 需 `--collect-submodules backend` + `--paths .`。
