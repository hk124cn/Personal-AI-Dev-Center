# 2026-11-18（凌晨）

## 用户「没看到」本地项目选项 → 可发现性问题

### 排查结论：功能是好的，是**藏得太深**

1. 查进程确认用户跑的是**新包**（`D:\app\...\dist\Personal-AI-Dev-Center.exe`，00:00:44 启动，我 23:54 换的）
2. 真实浏览器打开「新增项目」弹窗 → 服务器下拉**第一个就是「本地（仅本机，未部署）」** ✅
   （7 个选项：本地 + 6 台云主机）
3. **但用户看不到，两个原因**：
   - 下拉**默认选中第一台服务器**，「本地」要**点开下拉**才看得到
   - **「本地项目」分组空时被过滤掉**（`filter(g=>g.projects.length>0||g.server.status==='online')`）
     → 这个功能在列表里**完全不可发现**

### 修法（可发现性）

1. **「本地项目」分组即使为空也显示**，空时给引导文案：
   「这里放『只在本机、没部署到任何服务器』的项目。点『新增项目』时把『服务器』选成『本地（仅本机，未部署）』即可。」
   + 一个「+ 新增项目」按钮
   → 过滤条件加 `|| g.server.id===''`
2. **版本号 bump 到 1.4.28** —— 上一次是 1.4.27（加了本地项目但没 bump），
   用户无法分辨新旧包，这次必须区分

### 教训（重要）

**功能做完 ≠ 用户能看到。** 这次连续两次「用户说没看到」：
- 第一次（11-03）：版本号没 bump → 用户以为没更新
- 第二次（11-18）：功能入口太隐蔽 → 用户以为没这功能

→ **以后加功能要同步想「用户从哪发现它」**，尤其是：
- 新入口要在**空状态也可见**（别让功能藏在「有数据才出现」的地方）
- **版本号每次改动都要 bump**（`run_checks` 已有检查兜底）
