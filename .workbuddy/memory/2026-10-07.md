### 三件套（v1.4.24，commit `55eeef1`）

**① 硬超时 —— `backend/llm_analyzer.py`**

```python
LLM_HARD_TIMEOUT = int(os.environ.get("DEV_CENTER_LLM_HARD_TIMEOUT", "180"))

pool = ThreadPoolExecutor(max_workers=1, thread_name_prefix="llm-call")
future = pool.submit(call_llm_api, prompt, llm_config)
try:
    result, err = future.result(timeout=hard)
except FuturesTimeout:
    return None, f"硬超时 {hard}s"
finally:
    pool.shutdown(wait=False)   # 不 join，挂起的请求线程自生自灭
```

- 为什么必须另加一层：`requests.post(timeout=120)` 只限制「连接建立」与「两次读取之间」，
  对 DNS 解析、TLS 握手、代理下半开连接**都不生效** → 实测单项目挂了 4669s。
- `shutdown(wait=False)` 是关键：默认 `with ThreadPoolExecutor` 退出会 join，等于没超时。
- 实测：模拟挂起 30s + timeout=2 → **2.02s 放弃**；正常返回 0.00s，不受影响。

**② 增量跳过 —— `backend/sync.py`（收益最大的一项）**

- `_md_fingerprint(md_contents)`：排序后拼 `文件名 + 正文` 取 md5。
- `_llm_signature(llm_config)`：`provider|model|base_url`。
- 两者都没变 且 上一轮 `llm_analyzed=True` → 直接复用 `llm_summary/features/architecture/
  routes/tech_stack`，并把那时的 `todos/issues` 一起带回，**一个请求都不发**。
- `latest.json` 新增 `llm_input_fp` / `llm_config_sig`；新状态 `llm_status='reused'`。
- 换模型或 md 改了会自动重算（签名/指纹变了）——正好满足用户「要能切换付费模型」的需求。

**③ 失败熔断 —— `backend/sync.py`**

- `_update_llm_breaker(consec_fail, breaker_open, status)`：
  `api_failed` 连续到 `LLM_BREAKER_THRESHOLD`（默认 2，可用 `DEV_CENTER_LLM_BREAKER` 覆盖）
  → 打开熔断，本轮后续项目 `llm_status='skipped_breaker'`。
- **reused 不算成功**（没发请求，不能证明 provider 恢复），计数不变；`analyzed` 归零并撤销熔断。
