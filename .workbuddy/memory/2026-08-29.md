# 2026-08-29 便携版双击启动不了（taskkill 自杀）+ 简化为只检测提示

## 现象（用户报告）
双击 `dist/Personal-AI-Dev-Center.exe` 启动不了；但解压目录（tmp/win-unpacked）下的 `Personal AI Dev Center.exe` 能启动。

## 根因
`electron/main.js` 旧 `clearStalePort()` 按镜像名 `taskkill /F /IM "Personal-AI-Dev-Center.exe" /T`。
便携版进程树：`Personal-AI-Dev-Center.exe`（artifactName 自解压启动器，＝本进程的**父进程**） → `Personal AI Dev Center.exe`（productName 真正的 Electron 主进程＝本进程）。
taskkill 命中**父启动器**，`/T` 顺进程树把本进程一起杀掉 → 双击无窗口；后端 exe 因在 taskkill 之后才 spawn，侥幸存活成孤儿、继续占 8765。
（代码注释原以为"taskkill /IM 不会终止调用者自身"——错误，它不杀自己，但会杀自己的父进程并 /T 顺藤杀回。）

## 用户意见
「杀进程搞得太复杂了，就启动时检查一下有没有相关进程在跑。已经在跑了，弹提示，关闭。等使用者自己去杀进程就行。」——采纳，移除全部杀进程逻辑。

## 修复（commit 662df79）
- 删除 `clearStalePort()` 全部 `taskkill`。
- 新增 `isAnotherInstanceRunning()`：`netstat -ano | findstr :8765` 取 LISTENING PID → `tasklist /FI "PID eq ..."` 确认镜像名含 `Personal AI Dev Center.exe` → 返回 true。
- 顶层 lifecycle：`isAnotherInstanceRunning()` 为真 → `dialog.showErrorBox('已在运行…')` + `app.quit()`；否则保留 `requestSingleInstanceLock()` 兜底。
- `startBackend()` 删除 `clearStalePort()` 调用。

## 验证
- `node --check` 通过；`npm run build` EB_EXIT=0；asar grep 确认新代码进包。
- ⚠️ **沙箱无显示环境，Electron GUI 应用起不来后端**：连用户能启动的解包版在沙箱也 9–12s 退出、无进程无监听，日志仅 `registration_protocol_win.cc CreateFile: 系统找不到指定的文件`。故无法在此端到端验证 GUI 启动；真机逻辑应正常，已请用户在真机双击验证。
